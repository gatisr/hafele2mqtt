# Design: architecture, platforms and deliberate omissions

Back to the [README](../README.md).

## Architecture

- `app/config.py` loads and validates the `.connect` file, reads the environment, and plans the bridge's unicast address. Every failure here is a `ConfigError` with a one-line, actionable message.
- `app/model.py` turns the export into the entity model. Pure data, no I/O, which is what makes `--validate` and the unit tests possible.
- `app/state.py` persists the sequence number, IV index, published discovery topics and the GUID to `unique_id` map that keeps entities stable across re-addressing.
- `app/overrides.py` applies the optional `entities.yaml`, and writes one out for `--dump-overrides`. Opt-in from end to end: with no file, applying it is never called.
- `app/mesh.py` is a minimal Bluetooth Mesh network/transport/access layer: the k2/k3/k4 key derivations, network PDU encryption and obfuscation, proxy configuration messages in both directions, and decoding of incoming unsegmented access messages. Unsegmented, which is all the Light Lightness and Scene models need here: the longest thing the bridge sends is half of what one access message carries, and an oversized payload is refused rather than built. A decoded message reports its sequence number, its IV index and whether it was segmented, so the caller above can tell a replay from a new message and a message it cannot reassemble from one that never came.
- `app/adapter.py` is everything to do with the Bluetooth adapters themselves: enumerating them over BlueZ's ObjectManager, matching one by `hciN` name or by MAC, and power-cycling it. The parsing is split from the bus work, so the part that is easy to get wrong is testable without a radio.
- `app/ble.py` is the GATT Mesh Proxy link: choosing the adapter that can actually hear our network, discovery by network ID with a BlueZ-cache fallback for a proxy that has stopped advertising, notify handling, proxy SAR for PDUs larger than the MTU (which is nearly all of them, and the inbound half is bounded, typed from the first fragment and cleared whenever the link changes state, because anyone in radio range can feed it), and a supervisor that reconnects with capped exponential backoff, names which of the three failure states it is in, and escalates through a recovery ladder instead of repeating itself.
- `app/broker.py` configures every MQTT client the bridge makes, credentials and TLS alike, and runs the preflight that tells "unreachable", "rejected your password" and "that port is not speaking the protocol you think" apart. One function configures both clients so the probe cannot test a connection the bridge does not make.
- `app/main.py` is the bridge itself: discovery publishing, command handling, polling, shutdown. `CommandQueue` in it is the bounded, coalescing queue that incoming commands pass through.

## Supported platforms

Built and verified on `linux/arm64` and `linux/amd64`. On both, importing the modules and deriving mesh keys produce identical results. `.github/workflows/docker.yml` builds that pair as a single multi-arch manifest on every push and publishes it to GHCR on a `v*` tag, so `compose.yaml` can point at the published image instead of `build: .` if you would rather not build locally.

`linux/arm/v7` is **not** supported. No armv7 wheels are published for `cffi` (a `bleak` dependency) or for `cryptography`, so both would be compiled from source on every build, which needs `gcc`, `libffi-dev`, `pkg-config`, OpenSSL headers and a Rust toolchain in the image. The build fails on `cffi` as-is. On a Raspberry Pi, use a 64-bit OS.

## Deliberate omissions

These are decisions, not oversights.
Each one is a trade-off that would cost more than it buys in the setting this bridge is built for: one container, one LAN, one broker.

- **MQTT TLS is off by default, not absent.** Plaintext is what every existing deployment already has and what a broker on the same LAN usually wants, and the right setting cannot be guessed from the port, so it stays a choice: see [MQTT over TLS](mqtt.md#mqtt-over-tls). What is deliberately missing is client certificate authentication, which no broker here needs and which would add a second pair of paths to mount and keep valid.
- **The container runs as root, with the host's D-Bus socket.** Talking to BlueZ over D-Bus needs either root or a polkit policy granting `org.bluez` to a specific uid, and with `network_mode: host` and a bind-mounted system bus there is no uid mapping that works across hosts, so there is no `USER` line in the Dockerfile. Be clear about what that is worth to an attacker: `/var/run/dbus` is the host's own system bus, so a process that gets out of this container is talking to the host's services as root, and the mesh keys are mounted in alongside. Run it on a machine you trust, not on a shared box. If you want to drop the privilege anyway, the route is a polkit rule allowing `org.bluez` for one uid plus a matching `USER` in the Dockerfile; it works, it is specific to your host's polkit version, and it is left to you deliberately rather than shipped half-tested. The process opens no listening socket of its own.
- **The `HEALTHCHECK` only reports the process, not the mesh.** The bridge touches `HEALTH_FILE` on every turn of its poll loop and `python -m app.health` reads how old that is, so an unhealthy container means the loop has stopped going round: the task died, the event loop is wedged, or a send is hung. It deliberately says nothing about whether the radio is up, because a reconnect is ordinary, restarting the container does not bring a radio back, and a warning that is usually on is a warning nobody reads. The limit is three poll intervals and never under 180 seconds, `HEALTH_MAX_AGE` overrides it, and an empty `HEALTH_FILE` switches the whole thing off. For the questions it does not answer, watch `hafele/bridge/status` on the broker, which is backed by an MQTT last will and goes to `offline` the moment the bridge stops, and `hafele/status`, which says whether the mesh is reachable.
- **No IV Update procedure**, see [The 24-bit horizon](mesh-internals.md#the-24-bit-horizon).
- **No transport-layer segmentation.** Not the same thing as the proxy fragmentation above, which is implemented and used constantly. This is the mesh's own way of splitting an access message across several network PDUs, and it buys nothing here: the longest message the bridge sends is well inside what a single unsegmented one carries, and building an oversized one raises rather than putting a PDU on air that every node would discard without a word. The cost is in the other direction, where it is not the bridge's choice what a node sends: a segmented message cannot be reassembled, so it is named in the log once per node rather than dropped silently, which is the part that was actually worth fixing. Implementing the full procedure means an acknowledgement timer, a block acknowledgement, retransmission and a reassembly window per peer, for messages this network does not send.
- **Replay protection for incoming messages is not written to disk.** The bridge remembers the newest sequence number it accepted from each node and refuses anything older, which is what stops a recorded status message being replayed back at it as current. That table lives in memory only. Persisting it would mean a durable write per status message, several times a minute forever, and buys protection against a replay timed to land in the seconds between a restart and the start-up poll, whose entire effect would be one light showing a stale brightness until that poll corrects it.
- **Nothing renames an entity that already exists.** The bridge could switch every `unique_id` to the GUID it is anchored on, which would be tidier, and would silently orphan every entity now in service along with the automations naming them. It does not, and it will not do it quietly if it ever does: that would be a one-time migration you asked for, with the old topics retracted and the new ones published, not a side effect of an upgrade. The same reasoning is why `default_entity_id` and `suggested_area` are left to apply at creation only rather than being forced.
